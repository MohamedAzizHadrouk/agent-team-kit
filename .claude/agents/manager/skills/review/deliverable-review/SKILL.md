# Review a deliverable

## Checklist
- [ ] **Report format** complete (STATUS, SUMMARY, DELIVERABLES, HOW TO VERIFY, ASSUMPTIONS, OPEN QUESTIONS, RISKS, SKILLS USED).
- [ ] **Acceptance criteria**: check each one against the deliverable itself (open the file / link), not the summary.
- [ ] **Client isolation**: nothing from another client (names, assets, copy, code).
- [ ] **No fabrication**: no invented stats, testimonials, sources; claims trace back to the brief or a cited source.
- [ ] **Brand**: colours, fonts, voice and languages match BRAND.md / ENTITY.md.
- [ ] **Gates**: nothing published, deployed to prod, sent or paid without recorded approval.
- [ ] **Privacy**: no secrets, no personal data, likeness only with recorded consent.
- [ ] **Skills**: the relevant skills from the specialist's INDEX were used (e.g. WCAG check on a design, OWASP review on auth code).

## Feedback when it fails
Per problem: what is wrong → where (file / slide / line) → what "good" looks like. Max 5 points, most important first.
